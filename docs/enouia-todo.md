复核时补测出一处闸门的过度拦截：图片引用是正则扫全文，围栏代码块里的示例图片会被当成真实引用，于是一篇讲 Markdown 语法的文章会被拒。方向是安全的一侧，但接生产前要改成按解析结果取图片引用。

**草稿的生产同源预览也已完成**（ADR 13.17）：预览不另写渲染器，直接调 `tools/build-baselines.mjs` 的 `createPublicRenderer()`，并断言四篇夹具的预览与 `fixtures/baseline/` 逐字节相等；路由排在会话与 CSRF 守卫之后，未发布的草稿不会被匿名渲染出来。界面上写明这是渲染同源，不是外观同源。

预览第一次真跑就查出一个从 13.13 起就存在的缺陷（ADR 13.18）：`MoriiumImage` 的 priority 压过 paragraph，ProseMirror 补空文档时挑中了它，于是**每打开一篇文章，自动保存都会把一个 `![]()` 写回正文**。已修并有钉住机制的断言，但**已经保存的版本不会自己变干净**。

**B4、B9、B10 也已演练完**（ADR 13.20），用的是独立端口与独立库，没有碰 Morii 一直开着的那个实例。375 像素下无横向溢出、改稿与自动保存都成立；杀掉进程重启后最后一次自动保存还在、读者看到的内容没变。

演练查出两个真问题并当场修掉：数据库写入争用此前返回 500「Unexpected server error」，`db-locked` 这个建模过、也已映射成 503 的错误码**从来没有人抛出过**；API 断开时作者读到的是 `TypeError: Failed to fetch`。现在争用会被正确分类为可重试，界面也改成讲人话并说明改动还在编辑器里。**没修的是自动保存失败后不会自动重试**，那要连着界面一起想，所以 B10 记「部分」。
