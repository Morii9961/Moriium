# Token 采集口径交接：Moriium → Enouia Runtime

日期：2026-10-18。本文交接本次已实现的采集核对工具和后续设计，未修改 Runtime，也不代表它已接管生产。操作入口见 [activity.md](activity.md)，字段、算法和限制见 [codex-token-collection.md](codex-token-collection.md)。

## 本次结论

Codex 的 `account/usage/read` 返回日桶总量，没有缓存分项。不能仅凭缺少字段推断它排除了缓存，也不能把完整跨设备覆盖写成已验证事实。本机对照更接近“账号总量已包含缓存”的解释，但接口没有给出足以作保证的字段定义。

本次公开构建快照更新为 Codex **3,725,297,924** tokens、Claude Code/Cowork **5,808,932,805** tokens。GitHub 快照保留原值和时间。仓库中的 JSON 与已发布的线上状态须分别核实，推送成功本身不等于发布验收。

独立本地 Codex 核对报告观测到 **3,399,567,995** tokens，其中缓存读取 **3,230,672,140**，约占总量 **95.03%**。这是全部可用本地历史，扫描 818 份日志，有效用量覆盖 2026-06-03 至 2026-10-18、77 个有记录的 UTC 日期；没有限于一周。账号侧保留序列从 2026-05-12 开始。两者的覆盖范围、截点和日界不同，不能相加、逐日取较大值或相减后宣称得到了“缺失缓存”。

全历史交叉核对的去重 `last_token_usage` 总和为 **3,399,324,505**。与累计差值法相差 **243,490** tokens，差异定位在 2026-07-22 的一处累计缺口。本次扫描从 `2026-10-18T14:10:31.770Z` 开始，最后观测事件为 `14:10:41.179Z`；之后新增消耗不属于这个截点。

## 已实现的边界

- `scripts/lib/codex-usage.ts`：保留账号来源，校验日桶及安全整数总和；清理 app-server 失败后的超时计时器。
- `scripts/lib/codex-local-usage.ts`：只读 `CODEX_HOME` 下两类会话目录，支持普通和 Zstandard 压缩日志，按会话合并续接文件、去重并计算累计差值，报告异常。
- `pnpm activity:codex-local`：写入被忽略的 `.cache/activity-codex-local.json`。只保留计数、日期、覆盖标签和诊断，不输出原始会话、身份、路径或凭据。
- `pnpm activity:refresh codex/claude`：继续更新各自既有来源；Claude 含发现的本机 Cowork store，保留因日志清理而下降的旧日较高值。
- 本地核对工具没有进入定时采集和上传链路；没有注册任务、改写生产 pending/sequence 或修改 Runtime 数据目录。

## Runtime 的目标设计

保留三层数据：本机证据、带来源的私有用量账本、公开日汇总。Activity 不进入 Memory、Context、Vault 或 Provider prompt。Runtime 的正式实现不得在运行时读取 Moriium 仓库。

| 层 | 建议保存 | 禁止混入公开输出 |
| --- | --- | --- |
| 本机适配器 | 选定的日志根、解析器版本、稳定事件身份、输入/缓存/输出分项、来源时间 | 原始对话、工具参数、认证文件 |
| 私有账本 | 事件去重键、累计基线、解析版本、缺口与回退诊断、来源和账户归属状态 | 本机路径、会话/账户身份、模型与费用 |
| 公开投影 | 现有三源、日值、采集时间、协议规定的指标和日期标签 | 一切未列入公开白名单的字段 |

Codex 本地公式是 `input + output`，缓存读写属于输入，reasoning 属于输出。Claude 固定日报的 `inputTokens` 则是非缓存输入，需要另加 `cacheReadTokens + cacheCreationTokens`。共享字段名不代表相同口径。

当前本地核对器是部分历史观测：本次有 15 行不完整 JSON、262 个无效事件、41 次计数回退、1 个累计缺口、2 个首事件缺口。已检查的无效样例中，last-call 占位记录出现分项全零而 total 非零，不能据此编造缓存分项。回退时仅使用明确的 last-call 计数。不能把这份报告改名为完整账本，也不能用它静默覆盖账号历史。它不识别同一日志根中的不同登录账户；部分截断压缩流和采集期间的写入也可能留下缺口。

## 接手顺序与验收

1. 在 Runtime 当前 checkout 核实 `crates/enouia-activity/src/codex.rs`、Activity 运行器和公开契约。2026-10-18 的只读检查显示它仍转换账号日桶；本交接没有实现 Runtime 本地适配器。
2. 先用合成普通/压缩日志实现独立适配器和私有账本。覆盖重复通知、续接分片、父子继承、跨日、计数回退、首事件缺口、坏行、读取失败、安全整数溢出和截断压缩流。固定解析版本，未知格式显式报错或标记不完整。
3. 保留账号总量和本地明细两条独立 basis。界面应显示来源、日界、采集时间和完整性；不能将“未记录”说成“没有消耗”，也不能从配额百分比推算 token。
4. 如要改用本地记录作为公开 Codex 来源，先共同设计版本化 basis/timezone 迁移。当前 ActivityData v1 的 `Codex` 标签专指账号日界，本地 UTC 不能冒用它。不得单方面放宽 Moriium/Runtime 校验。
5. 生产接管须另行核对最新归档、现有写入者和 pending 序号；旧 pending 按原字节重试。只上传日汇总，观察公开 JSON 的版本、哈希和采集时间后，才能确认发布。不得用本次 Moriium 读取/推送授权替代未来 Runtime 的账户访问、迁移、生产上传或调度授权。
